WHAT EACH BUTTON CAN ACTUALLY CARRY Only the copy and share-sheet paths can carry the message. FACEBOOK cannot: it ignores any text passed as a parameter and builds its card solely from the target page's og: tags — so the tagline reaches Facebook through og:description on the product page, not through this button. FACEBOOK works the way you would expect: sharer.php takes the URL, Facebook fetches it, and builds the card from the page's og: tags. Nothing else is needed — and notably, passing a title or image as parameters does nothing, since Facebook stopped honouring those years ago and reads only the target page. TIKTOK HAS NO WEB SHARE URL. There is no tiktok.com/share?url= equivalent to Facebook's sharer; TikTok's sharing is app-side only, and its Share Kit is an SDK for sharing *video files from your own app*, not links from a website. Any "TikTok share button" that claims otherwise is either opening the app's homepage or silently doing nothing. So the TikTok button does the only honest thing available: it opens the device's native share sheet via the Web Share API, which lists TikTok among the targets when the app is installed. Where that API does not exist — every desktop browser except Safari — it falls back to copying the link, because pasting into the app is the actual workflow on desktop anyway. The label changes to match what will happen, so the button never promises something it cannot do. {% endcomment %} {% comment %}Renders nothing without a URL.
