{% comment %} One product as a table row — the dense counterpart to _product_card.html. WHY THIS EXISTS The grid is a browsing layout: six image tiles per row, 187px wide, names truncated to two lines. That is the right shape for recognising a product you half-remember, and the wrong shape for the job this screen is actually used for — selecting forty rows and doing one thing to them. At 187px the checkbox is a 16px target sitting on top of a photo, the SKU is not shown at all, and a screen holds 24 products. A row holds the same product in a quarter of the height, shows the SKU and the category and the tags as text you can read down a column, and puts every checkbox in one vertical line so a selection is a single downward drag of the eye rather than a hunt across a grid. Both are kept because both are right sometimes. The toggle remembers which you picked. CONTRACT WITH THE SELECTION CODE The checkbox carries class="product-row-check" and value="{{ product.id }}", exactly as the card does, and calls the same updateProductBulkBar(). Every existing function — getSelectedProductIds, toggleSelectAllProducts, clearProductSelection — walks those two attributes and therefore works here untouched. The view toggle swaps which container is visible; it does not swap the selection model. {% endcomment %} {% with product.images.all|first as img %} {% if img %} {% comment %}src, not image.url — an imported row may hold only a supplier CDN link because the download failed.
